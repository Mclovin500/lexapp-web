# ESPECIFICACIÓN DE PANTALLAS Y FLUJO DEL ABOGADO — LEXAPP

## 1. Objetivo del documento

El presente documento define la estructura funcional, navegación y comportamiento de la **plataforma web de LexApp destinada exclusivamente a abogados**.

Su objetivo es servir como guía para la persona encargada del desarrollo, explicando qué función cumple cada pantalla, desde dónde se accede, qué información debe mostrar y hacia dónde debe continuar cada flujo.

La plataforma del abogado funciona de manera independiente de la aplicación móvil del cliente.

> **Importante:** este documento corresponde únicamente al entorno del abogado. Las funciones, pantallas y flujos exclusivos del cliente no forman parte de esta especificación.

---

# 2. Alcance de la plataforma web del abogado

La plataforma permite al abogado:

- Crear y administrar su cuenta profesional.
- Verificar su correo electrónico.
- Proporcionar sus credenciales profesionales.
- Consultar el estado de validación de su perfil.
- Iniciar sesión de manera segura.
- Recuperar su contraseña.
- Consultar su Dashboard.
- Recibir solicitudes de clientes.
- Revisar solicitudes y necesidades legales.
- Crear propuestas de servicios.
- Dar seguimiento a las propuestas.
- Administrar expedientes.
- Consultar documentos de expedientes.
- Consultar información de clientes.
- Comunicarse mediante chat.
- Administrar reuniones virtuales.
- Realizar videollamadas.
- Administrar honorarios y cobros.
- Crear cobros adicionales relacionados con expedientes.
- Consultar movimientos y estados de pago.
- Configurar la cuenta donde recibirá sus honorarios.
- Administrar su perfil profesional.
- Configurar opciones de seguridad y preferencias.
- Recibir notificaciones relacionadas con su actividad.

---

# 3. Separación entre plataformas

LexApp utiliza dos entornos diferentes:

### Plataforma web — Abogado

Es el entorno definido en este documento.

El abogado utiliza una computadora o dispositivo de escritorio para administrar su actividad profesional.

### Aplicación móvil — Cliente

El cliente utiliza la aplicación móvil para buscar abogados, contratar servicios, realizar pagos, consultar sus casos y comunicarse con el abogado.

**No se deben mezclar las funciones de ambos perfiles.**

En particular:

- El abogado no utiliza la aplicación móvil para administrar sus expedientes.
- El abogado no recibe pagos mediante una pantalla de tarjeta del cliente.
- El abogado no busca abogados.
- El cliente no utiliza el Dashboard del abogado.
- El cliente no administra cobros profesionales.
- El cliente no configura la cuenta bancaria del abogado.

---

# 4. Estructura general de navegación

La plataforma del abogado se divide en:

### Acceso y registro

- A1 — Bienvenida.
- A2 — Inicio de sesión.
- A2A — Verificación de código de seguridad.
- A2B — Recuperar contraseña.
- A2C — Código de recuperación.
- A2D — Nueva contraseña.
- A3 — Registro básico.
- A3A — Verificación de correo.
- A4 — Credenciales profesionales.
- A5 — Área de práctica y perfil.
- A5A — Estado de validación profesional.

### Panel principal

- B1 — Dashboard.
- B1A — Centro de notificaciones.

### Solicitudes

- C1 — Solicitudes recibidas.
- C2 — Detalle de solicitud.

### Propuestas y servicios

- D1 — Crear propuesta de servicio.
- D2 — Seguimiento de propuestas.
- D3 — Honorarios y cobros.
- D4 — Crear cobro adicional.
- D5 — Detalle de pago y movimientos.

### Expedientes

- E1 — Mis expedientes.
- E2 — Detalle del expediente.
- E3 — Documentos del expediente.

### Clientes

- F1 — Directorio de clientes.
- F2 — Detalle del cliente.

### Agenda y comunicación

- G1 — Agenda de citas virtuales.
- G1A — Sala de videollamada.
- H1 — Chat con clientes.

### Perfil y configuración

- I1 — Perfil profesional.
- J1 — Configuración.
- J1A — Cuenta de depósito / honorarios.

Esto representa **31 pantallas/vistas internas identificadas para el entorno del abogado**.

# 5. ESPECIFICACIÓN DE LAS 31 PANTALLAS DEL ABOGADO

## A1 — Bienvenida

### Objetivo

Presentar la plataforma LexApp y proporcionar el acceso inicial al entorno del abogado.

### Elementos

- Logotipo de LexApp.
- Nombre de la plataforma.
- Mensaje introductorio.
- Botón para iniciar sesión.
- Acceso al registro.

### Navegación

- Iniciar sesión → A2.
- Crear cuenta → A3.

### Consideraciones

Es una pantalla pública de acceso. No debe mostrar información privada del abogado.

---

# A2 — Inicio de sesión

### Objetivo

Permitir que un abogado registrado acceda a su cuenta.

### Elementos

- Correo electrónico.
- Contraseña.
- Mostrar/ocultar contraseña.
- Botón "Iniciar sesión".
- Enlace "¿Olvidaste tu contraseña?".
- Opción para crear una cuenta.

### Navegación

Credenciales correctas:

**A2 → A2A**

Recuperación de contraseña:

**A2 → A2B**

Registro:

**A2 → A3**

### Consideraciones

Las credenciales deben validarse mediante el sistema de autenticación.

No se debe enviar directamente al Dashboard hasta completar el mecanismo de seguridad establecido.

---

# A2A — Verificación de código de seguridad

### Objetivo

Confirmar la identidad del abogado después de introducir correctamente sus credenciales.

### Elementos

- Título "Verifica tu identidad".
- Correo parcialmente oculto.
- Seis campos para el código.
- Botón "Verificar código".
- "Reenviar código".
- Temporizador.
- Opción para regresar.

### Navegación

Código correcto:

**A2A → B1**

Código incorrecto:

Permanecer en A2.

Código vencido:

Solicitar un nuevo código.

### Consideraciones

El código debe:

- Ser temporal.
- Tener un tiempo de expiración.
- Ser de un solo uso.
- Invalidarse cuando se genere uno nuevo.
- Tener un límite de intentos.

No mostrar el código real en pantalla.

---

# A2B — Recuperar contraseña

### Objetivo

Permitir al abogado iniciar el proceso para recuperar su contraseña.

### Elementos

- Título "Recuperar contraseña".
- Campo de correo.
- Botón "Enviar código de recuperación".
- Enlace para regresar al inicio de sesión.

### Navegación

Solicitud enviada:

**A2B → A2C**

Regresar:

**A2B → A2**

### Consideraciones

El sistema no debe revelar información sensible sobre la existencia de cuentas.

---

# A2C — Código de recuperación

### Objetivo

Verificar que el abogado tiene acceso al correo utilizado para recuperar su cuenta.

### Elementos

- Correo parcialmente oculto.
- Seis campos de código.
- Botón "Verificar código".
- "Reenviar código".
- Temporizador.
- Opción para regresar.

### Navegación

Código correcto:

**A2C → A2D**

Código incorrecto:

Permanecer en A2C.

Código vencido:

Solicitar otro código.

---

# A2D — Nueva contraseña

### Objetivo

Permitir al abogado establecer una nueva contraseña.

### Elementos

- Nueva contraseña.
- Confirmar contraseña.

**A2D → A2**

### Elementos

Código correcto:

**A3A → A4**

Código incorrecto:

Permanecer en A3A.

### Consideraciones

Esta pantalla es diferente de A2A.

- **A3A:** verifica el correo durante el registro.
- **A2A:** verifica la identidad durante el inicio de sesión.

La información profesional debe validarse de acuerdo con el mecanismo que se implemente.

No mostrar una credencial como "verificada" si el sistema todavía no ha realizado la validación.

- Importe.

### Navegación

Después de crear:

**D4 → D5/D3**

### Funcionamiento

El cobro generado debe:

1. Asociarse al expediente.
2. Registrarse en el sistema.
3. Generar una notificación al cliente.
4. Permitir que el cliente lo pague desde su aplicación móvil.
5. Actualizar posteriormente el estado del pago para el abogado.

El abogado no realiza el pago desde esta pantalla.

# 6. FLUJOS COMPLETOS DEL ABOGADO

## 6.1. Primer acceso

**A1 → A2**

El abogado llega a la pantalla de inicio de sesión.

---

## 6.2. Inicio de sesión

**A2 → A2A → B1**

1. El abogado introduce sus credenciales.
2. El sistema valida usuario y contraseña.
3. Se envía el código de seguridad.
4. El abogado introduce el código.
5. Si es correcto, accede al Dashboard.

---

## 6.3. Recuperación de contraseña

**A2 → A2B → A2C → A2D → A2**

1. Selecciona "¿Olvidaste tu contraseña?".
2. Introduce su correo.
3. Recibe el código.
4. Introduce el código.
5. Define una nueva contraseña.
6. Regresa al inicio de sesión.

---

## 6.4. Registro del abogado

**A3 → A3A → A4 → A5 → A5A**

1. Introduce sus datos básicos.
2. Verifica su correo.
3. Introduce sus credenciales profesionales.
4. Define sus áreas de práctica y perfil.
5. Envía la información para validación.
6. Consulta el estado de la validación.

Cuando corresponda:

**A5A → B1**

---

## 6.5. Solicitud de cliente

**B1 → C1 → C2 → D1 → D2**

1. El abogado recibe una solicitud.
2. Consulta las solicitudes.
3. Abre el detalle.
4. Analiza la necesidad.
5. Prepara una propuesta.
6. La envía al cliente.
7. Consulta posteriormente el estado de la propuesta.

---

## 6.6. Propuesta aceptada

**D2 → E1/E2**

Cuando una propuesta es aceptada y el caso queda establecido:

1. Se registra la relación profesional.
2. Se crea o habilita el expediente correspondiente.
3. El abogado puede administrarlo desde E1.

# 9. REGLAS QUE DEBEN RESPETARSE

### 9.1. El abogado no administra tarjetas del cliente

El cliente realiza sus pagos desde la aplicación móvil.

El abogado solamente:

- Crea cobros.
- Consulta pagos.
- Consulta estados.
- Administra la información relacionada con sus honorarios.

### 9.2. Las reuniones son virtuales

No incluir:

- Oficinas.
- Direcciones.
- Mapas.
- Citas presenciales.

### 9.3. Los documentos pertenecen a expedientes

No crear un módulo independiente de documentos sin relación con un caso.

### 9.4. El abogado solamente accede a información autorizada

Los datos del cliente, documentos, mensajes y expedientes deben estar protegidos mediante permisos.

### 9.5. La validación profesional debe ser real

No mostrar "Cédula verificada" o "Abogado validado" únicamente porque el abogado introdujo un número.

Debe existir un mecanismo real de validación antes de mostrar ese estado.
